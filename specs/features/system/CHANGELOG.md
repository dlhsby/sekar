# System — Changelog

Newest first. Feature overview + current design live in [README.md](./README.md).

- 2026-08-01 — **Swept every page for the same pattern; four more were still pulling the full lokasi list.** A page-by-page pass over the whole dashboard (16 routes, Chromium) found `/activities`, `/users`, monitoring's hierarchy filter and `/export` still calling `useLocations()` for what is only a name in a dropdown. All four now use the lookup; the two that filtered by rayon **server-side** now filter one cached list **client-side**, which also removes a refetch every time the operator drills to another rayon. Measured: **`/activities` 1.56 MB → 216 KB, `/users` 2.80 MB → 1.46 MB**. The sweep found no errors on any route. What is left is deliberate: `/users` keeps its own 0.80 MB user list (the admin grid needs assigned-area counts, deactivated rows and pagination metadata) and `/locations` keeps 1.52 MB (952 rows with every column plus the boundary its map link draws). be 2703 · web 2187.
- 2026-08-01 — **`GET /locations` was 12.5 MB because of the rayon it joined, not the lokasi it returned.** The management table hydrated both relations whole (`leftJoinAndSelect`), and a **District carries its own `boundary_polygon`** — so ~11 KB of rayon GeoJSON was stamped onto every one of the 952 rows: **10.8 MB of the 12.5 MB**. The grid reads a rayon NAME and a type name/code/category, so both joins now carry explicit column lists. **12.5 MB → 1.59 MB, 0.44 s → 0.10 s**; the `/locations` page as a whole went **12.5 MB → 1.88 MB**. The lokasi's own `boundary_polygon` is **kept**: it is only 0.6 MB and the grid genuinely uses it — a yes/no column with a filter, and the per-row map link that draws the shape. Removing it first turned every "Batas Wilayah" cell to "TIDAK ADA", which is how the real consumer was found. **Not a bug after all:** `/assets` answering 403 to a superadmin is deliberate — three tests in `assets.service.spec.ts` assert that `admin_system`, `superadmin` and `kepala_rayon` are denied asset *viewing* while remaining in `ASSET_MANAGERS`. Odd-looking, but it is a tested policy decision, so it stands. be 2703 · web 2187.
- 2026-08-01 — **The lookup pattern applied beyond Jadwal: four more pages stop downloading 12.5 MB.** The schedules work left `useLocations({ limit: 1000 })` and `useUsers({ limit: 1000 })` in place elsewhere, and they are the same trap: the first sends no page/limit at all (that is how it dodges the controller's 100-row clamp), so the backend returns **every** lokasi as a full entity with a nested district and boundary polygon — **12.5 MB**; the second pages the full user entity twice — **928 KB**. Both to read a name. Migrated 4 lokasi consumers (`UserForm`, `TaskFormModal`, `/tasks/new`, `/plants`) and 7 petugas consumers (`OvertimeForm`, `TaskFormModal`, `LocationWorkersCard`, `/assets`, `/districts`, `/tasks/new`, `/locations`) to the existing `/locations/lookup` and `/users/lookup`. Measured in Chromium: **`/tasks/new` 13.5 MB → 532 KB · `/plants` 12.5 MB → 221 KB · `/assets` 928 KB → 137 KB · `/districts` ~1 MB → 263 KB**. The lokasi lookup gained `location_type_name` (a join, ~20 KB across 952 rows) because two pickers disambiguate duplicate lokasi names with it — there are genuinely two "Taman Korea" — and dropping the suffix would have made some options impossible to tell apart. **Bug found while migrating:** `/tasks/new` rendered `${a.name} (${a.code})`, but `code` has never existed on a lokasi, so every option read "… (undefined)"; it now shows the type. **Also:** `MAX_RANGE_ROWS` on `/schedules/range` came down **60 000 → 20 000**. The old ceiling existed to let the month grid fetch a whole month; since ADR-057 nothing asks for a wide unfiltered range (the board fetches one container, the grids read aggregates, mobile is self-scoped), so the largest legitimate request is ~1.2k rows and the guard is protective again rather than nominal. **Deliberately NOT migrated:** the `/users` and `/locations` admin grids, which legitimately need the full entity (assigned-area counts, deactivated rows, pagination metadata). be 2702 · web 2187.
