# Attendance — Changelog

Newest first. Feature overview + current design live in [README.md](./README.md).

- 2026-07-25 — **Shift settings: standard datagrid CRUD · `code` dropped · start/end reminders (ADR-055).** Four follow-ups on configurable shifts. (1) The Jadwal → **Shift** side sheet now lists shifts via our standard **`DataTable`** (search/sort/status-filter) showing **Name + Status** only; add/edit stays in a separate modal (single-column, 24h pickers) so it never dismisses the sheet. (2) **`shift_definitions.code` removed everywhere** — code, DB (new migration drops the column + `uq_shift_definitions_code`), seeds (now `ON CONFLICT (name)`), web/mobile types, the mobile picker/clock-in `shift_code` display fallbacks (→ `shift_name`), and docs. The code was internal and auto-generated; shifts are identified by their unique name. `findByCode` (no production caller) deleted. (3) **Dynamic-shift audit** — core logic was already dynamic; fixed the stale "3 fixed shifts" comments + the demo seed's `i % 3` round-robin (now rotates over however many shifts exist). (4) **Per-shift reminders** — new `start_reminder_min` (default **15**, preserving the legacy fixed window; 0 = off) and `end_reminder_min` (null = off) columns. The existing shift-start cron now reads `start_reminder_min` (fires in the 15-min bucket containing the configured lead); a new **`ShiftEndReminderCron`** pushes a `SHIFT_END_REMINDER` clock-out nudge before shift end (reads today + yesterday rosters so a night shift's end is caught after midnight). Both reminder types are user-toggleable. Tests: updated shift-definition service/controller + shift-reminder specs, new end-reminder cron spec; be/web/mobile tsc + web lint + i18n parity green.
- 2026-07-25 — **Configurable shift definitions (ADR-055 backlog → shipped).** Shift types are now operator-editable — 3 today, but any number (a single all-day shift, two, five…). Backend gained **CRUD** on `shift-definitions` (was GET-only): `POST` / `PATCH` / `DELETE` (soft), **system-managers only** (`USER_MANAGERS`), with unique name+code, HH:MM(:SS) time validation, auto-derived `crosses_midnight`, and per-shift `early_window_min`/`cutoff_grace_min` (the ADR-055 attribution window). Delete is **soft** so historical schedules/shifts/punches keep their reference; to just stop offering a shift, set `is_active=false`. Web: a **"Shift" toolbar button on the Jadwal page (left of "Hari Libur")** opens a `ShiftDefinitionsModal` (list + add/edit/remove; managers edit, others read-only). Verified end-to-end (CRUD + a non-manager 403). Tests: 6 service CRUD + updated controller specs; the web shift-definitions API client + mutations.
- 2026-07-25 — **ADR-055 adversarial-review fixes (multi-open sessions + explicit shift).** A 4-agent review of the whole punch surface surfaced three real defects, all from Phase-1 removing the single-open-shift guard (a worker can now hold a regular AND an overtime session at once): (1) **`clockOut` wasn't overtime-aware** — `findOne(clock_out_time IS NULL)` with no `is_overtime` filter could close the *wrong* session, so ending overtime might close the regular shift. `clockOut` gained an `isOvertime` param (default false); `overtime.endOvertime` passes `true`. (2) **explicit picker shift** — a `shift_definition_id` sent without `service_day` defaulted to *today* (wrong for a crossing shift chosen after midnight) and a bogus id could orphan a punch; `resolveClockInKey` now honors an explicit shift **only when it matches a real attribution candidate** (which supplies the correct service_day and rejects bogus/expired ids — else it falls through to auto-attribution). (3) **`activities.getActiveShiftOrFail`** now deterministically attaches to the regular session first (`is_overtime ASC, clock_in_time DESC`). Tests added for each; 819 backend tests green. (Discarded as false-positives/by-design: "double clock-in offline" — the punch model absorbs redundant clock-ins; picker "stale selection" — the effect re-selects on options change; `service_day NOT NULL` — kept nullable so the raw-SQL seed works, app always sets it.)
- 2026-07-25 — **Attendance UX consolidation — one Catapa-style hub.** Collapsed the two Menu tiles (Kehadiran history + Pencatatan Waktu record) into **one** "Pencatatan Waktu" tile → a new **`TimeRecordHubScreen`**: the empty-state line, today's date + shift, **Jam Masuk / Jam Keluar**, **Clock In / Clock Out** buttons, a **"Lihat Log Pencatatan Waktu"** link → the history list, and today's punch timeline inline (`LOG PENCATATAN WAKTU HARI INI`). The Clock In/Out buttons pass an explicit `action` to the record screen (`Absensi` route gains an optional `{ action }` param; `ClockInOutScreen` reads it via the route prop and pre-selects the label). The list + detail screens are now reached from inside the hub, not from separate tiles. Verified on the emulator against the Catapa reference. Tests: `TimeRecordHubScreen` (renders + routes Clock In/Out/Lihat Log), navigator route registry updated.
- 2026-07-25 — **[ADR-055](../../architecture/decisions/ADR-055-punch-attendance-model.md) offline-first punch queue.** Clock-in/out now work **offline** (ADR-002): the punch is enqueued (`offlineQueue`) with its **client uuid** and **capture time**, and the sync manager replays it when connectivity returns — idempotent on the uuid, so a replay is a server-side no-op. New optional **`punched_at`** on the clock DTOs records *when the worker actually punched*, not when the queue drained; the backend **clamps it to ≤ now** (a future/tampered time falls back to the server clock) and measures the min-duration guard against it. The mobile clock-in submit is no longer gated on connectivity (it queues); the offline banner copy updated. `ClockPunchOptions.punchedAt`; `syncManager` threads uuid + `punched_at` through. Tests: backend capture-time + future-clamp, syncManager replay assertions updated. **Deferred item cleared** — the offline replay the Phase-3 uuid was laid down for is now wired.
- 2026-07-25 — **[ADR-055](../../architecture/decisions/ADR-055-punch-attendance-model.md) Phase 4 — punch timeline (Log/Detail).** New **`GET /shifts/attendance/:date/punches`** returns the raw append-only punch log for a WIB service-day, grouped into sessions (per shift-definition / overtime) each with its derived Jam Masuk / Keluar / worked-minutes (`PunchLogDayDto`). The mobile **Detail Kehadiran** screen gained a **`PunchTimeline`** card (a "PENCATATAN WAKTU" section) rendering each session's clock-in/out punches with time + in/out-of-area — the read-only detail from the Catapa mockups. `shiftsApi.getPunchLog(date)`. Verified on the emulator against real data (satgas_barat_1_1's cross-midnight Shift-3 session). Tests: service grouping/derivation (regular + overtime split) + `PunchTimeline` render.
- 2026-07-25 — **[ADR-055](../../architecture/decisions/ADR-055-punch-attendance-model.md) Phase 3 (mobile) — Pencatatan Waktu menu tile + shift picker + punch idempotency.** New **"Pencatatan Waktu"** Menu tile (route `Absensi` → the clock-in/out record screen) for clockable roles, beside the "Kehadiran" history tile. The record screen gains a **shift picker** (`ShiftPickerSheet`) fed by `GET /shifts/current-state` — shown only when clocking in and the attribution window offers a choice (near midnight / dangling); the ranked options display phase (Akan mulai / Sedang berjalan / Baru selesai) + service-day, default pre-selected. Every clock-in/out now carries a **client uuid** (`react-native-uuid`) so a retry is idempotent server-side (offline-first foundation, ADR-002), plus GPS accuracy; the explicit picker shift is passed through. `shiftsApi.getCurrentState()` + `ClockPunchOptions` added. Tests: `ShiftPickerSheet` (select + default), updated clock-in call assertion. **Deferred:** the full offline punch-queue *replay* wiring (the uuid makes it safe to add) and the Log/Detail screens (Phase 4).
- 2026-07-25 — **[ADR-055](../../architecture/decisions/ADR-055-punch-attendance-model.md) Phase 3 (backend API) — current-state + shift picker + explicit selection.** New **`GET /shifts/current-state`** returns the worker's open session (Jam Masuk + context) **or null**, plus the ranked **shift options** a clock-in could target now (`ShiftOptionDto`: shift + `service_day` + `phase` early/covering/grace + `minutes_to_start` + `is_default`) — the payload the mobile "Rekam Waktu" screen uses to disable Clock Out when nothing is open and to offer the picker near midnight / for a dangling shift. `clockIn` now accepts an **explicit `shift_definition_id` + `service_day`** (the picker choice), which overrides auto-attribution when no session is open; open-session continuation still wins. The attribution candidate carries `shift_name`/`shift_code` for display. Enables the Phase-3 mobile UI (offline punch queue, picker) which lands next. Tests: current-state (open + null) + explicit-choice override.
- 2026-07-25 — **[ADR-055](../../architecture/decisions/ADR-055-punch-attendance-model.md) Phase 2 — near-midnight attribution window.** A clock-in is now attributed to the shift whose window `[start − early_window, end + cutoff_grace]` covers "now", picking the right `(shift_definition, service_day)` — so a post-midnight punch lands on **yesterday's** crossing shift, an early punch is offered up to `early_window` before start, and past `end + cutoff_grace` the shift drops out (an open session becomes a dangling `lupa_clock_out`). New per-shift-definition columns **`early_window_min` / `cutoff_grace_min`** (default 60, migration + CHECK ≥ 0) make it configurable per shift (the night shift can carry a longer grace). New pure **`ShiftAttributionService`** (ranks candidates: covering > early > grace, nearest start wins) + **`SchedulesService.getAttributionCandidates`** (yesterday+today PLANNED/PRESENT rows). Wired into `clockIn`'s fresh-session key; an open session still continues on its own key, and unscheduled/ad-hoc workers keep the legacy time-of-day resolution. Because attribution can put a session's first punch on a **different calendar day** than it belongs to, the projection now stores an **explicit `shifts.service_day`** (migration backfills it from the clock-in's WIB date) instead of deriving it from `clock_in_time` — otherwise a night worker's first clock-in at 00:30 (attributed to yesterday's Shift 3) would split its clock-out onto a different key and never close. **Presence/monitoring needs no change** — Phase 1 kept `shifts` a punch-derived projection and preserved the status-calculator emits, so `bertugas` already reflects punches. Tests: 10 resolver + attribution integration + candidate mapping; migration rehearsed on the sim clone. Also: `schedule.min_shift_duration_min` is now truly disableable (floor 0 = off).
- 2026-07-25 — **[ADR-055](../../architecture/decisions/ADR-055-punch-attendance-model.md) Phase 1 — punch log becomes the source of truth (backend cutover).** New append-only **`attendance_punches`** table + migration with an idempotent backfill from `shifts` (deterministic `md5(shift_id||':in'|':out')` ids). `shifts` is now a **maintained session-projection** — one row per `(user, service_day, shift_definition, overtime)`, stable `id`, rebuilt from the punches after every clock action — so the four FKs on `shifts.id` and all field-readers keep working untouched (Phase-0 correction from the "derived view" plan). New **`AttendanceDerivationService`** (pure: Jam Masuk=first-in, Keluar=last-out, open⟺last punch is clock-in, segment pairing absorbs redundant/re-entry ins, worked=Σ segments). `clockIn` no longer throws `SHIFT_ALREADY_ACTIVE` — a re-entry reopens the same session; `clockOut` still needs an open session (min-duration measured from the earliest open clock-in). Punches idempotent on an optional `client_uuid`. Historical `shifts` rows left as-is; only new clock cycles use the punch→projection path; readers stay on `shifts` this phase. **Rehearsed on the sim clone** (9522 shifts → 9522 in + 9172 out punches, 0 parity mismatches, re-run inserts 0). Tests: 14 derivation + 34 service + parity/idempotency on real data. Koreksi / overlap-block / `rayon_id` cleanup remain deferred.
- 2026-07-25 — **[ADR-055](../../architecture/decisions/ADR-055-punch-attendance-model.md): punch-log attendance model (design locked, not started).** Decided to re-base attendance from an open/closed `shifts` row to an **immutable punch log** — every clock-in/out is an append-only event; a shift's session (first-in / last-out / paired-segment hours / open?) is derived. Clock-in never blocks (removes an ADR-050 guard violation where a dangling shift blocked the next clock-in); clock-out needs a prior clock-in. A near-midnight **attribution window** (1 h early / 1 h cutoff, per-shift) resolves which shift a punch belongs to. Preserves the ADR-050 presence contract (only `bertugas`'s source moves) and ADR-053's per-shift invariant. **v1 approval-free**; **Koreksi Kehadiran** (correction + approval) and the `users.rayon_id` cleanup are deferred/companion tasks. `shifts` survives as a derived view through a reader-by-reader migration. No implementation yet.

- 2026-07-23 — **"Lokasi Anda" draws the right boundary, and it matches monitoring.** The map took its area from `currentShift?.area ?? assignedArea` — the ACTIVE clock-in or the *permanent* lokasi — skipping today's roster entirely, so a worker whose schedule sent them somewhere other than their permanent lokasi saw the wrong boundary, or none at all, on the very screen meant to answer "am I in my area?". The polygon is styled from the monitoring palette instead of the pruning-request one and is **tinted by whether the worker is inside it**, so it cannot contradict the badge above it, and the lokasi's own pin is drawn so the area stays identifiable when the worker is far outside it.
- 2026-07-23 — **Clock-in geofences against TODAY'S assignment, and shows all of it.** `useClockInOut` built its geofence from the standing `assignedAreas`, not the roster — so whenever today's assignment differed from the permanent one, clock-in was checked against the wrong lokasi. - 2026-07-22 — **Clock-in told the truth about lateness and scope (mobile).** (1) The attendance badge judged lateness from the *first clock-in*, which does not exist yet on the Clock In screen — so a Shift 1 (06:00–15:00) worker opening it at 21:54 was shown **TEPAT WAKTU**. `deriveAttendanceStatus` now projects against **now** ("if I clock in this second, am I late?") and adds an `outside_window` state for a shift whose window has already closed. (3) **"Jadwal Saya" added to the Menu grid** for every schedulable role — the screen existed but was reachable only from Profil.
- 2026-07-17 — **Fix ad-hoc clock-in 500 (`shifts.location_id` NOT NULL drift).** The `Shift` entity declares `location_id` nullable and `clockIn` explicitly allows an **ad-hoc clock-in with no area** (worker with no schedule + no assigned area; GPS still recorded), but the DB column was created `NOT NULL`, so that path threw a raw not-null constraint error (HTTP 500) instead of recording the shift. Migration `MakeShiftLocationNullable` drops the constraint to match the entity + intent. Behaviour-preserving (all existing shifts have a location); only the previously-impossible ad-hoc insert now succeeds (verified: `POST /shifts/clock-in` for an unassigned worker → 201 with `location_id: null`).
