# Attendance — Changelog

Newest first. Feature overview + current design live in [README.md](./README.md).

- 2026-07-25 — **[ADR-055](../../architecture/decisions/ADR-055-punch-attendance-model.md) Phase 1 — punch log becomes the source of truth (backend cutover).** New append-only **`attendance_punches`** table + migration with an idempotent backfill from `shifts` (deterministic `md5(shift_id||':in'|':out')` ids). `shifts` is now a **maintained session-projection** — one row per `(user, service_day, shift_definition, overtime)`, stable `id`, rebuilt from the punches after every clock action — so the four FKs on `shifts.id` and all field-readers keep working untouched (Phase-0 correction from the "derived view" plan). New **`AttendanceDerivationService`** (pure: Jam Masuk=first-in, Keluar=last-out, open⟺last punch is clock-in, segment pairing absorbs redundant/re-entry ins, worked=Σ segments). `clockIn` no longer throws `SHIFT_ALREADY_ACTIVE` — a re-entry reopens the same session; `clockOut` still needs an open session (min-duration measured from the earliest open clock-in). Punches idempotent on an optional `client_uuid`. Historical `shifts` rows left as-is; only new clock cycles use the punch→projection path; readers stay on `shifts` this phase. **Rehearsed on the sim clone** (9522 shifts → 9522 in + 9172 out punches, 0 parity mismatches, re-run inserts 0). Tests: 14 derivation + 34 service + parity/idempotency on real data. Koreksi / overlap-block / `rayon_id` cleanup remain deferred.
- 2026-07-25 — **[ADR-055](../../architecture/decisions/ADR-055-punch-attendance-model.md): punch-log attendance model (design locked, not started).** Decided to re-base attendance from an open/closed `shifts` row to an **immutable punch log** — every clock-in/out is an append-only event; a shift's session (first-in / last-out / paired-segment hours / open?) is derived. Clock-in never blocks (removes an ADR-050 guard violation where a dangling shift blocked the next clock-in); clock-out needs a prior clock-in. A near-midnight **attribution window** (1 h early / 1 h cutoff, per-shift) resolves which shift a punch belongs to. Preserves the ADR-050 presence contract (only `bertugas`'s source moves) and ADR-053's per-shift invariant. **v1 approval-free**; **Koreksi Kehadiran** (correction + approval) and the `users.rayon_id` cleanup are deferred/companion tasks. `shifts` survives as a derived view through a reader-by-reader migration. No implementation yet.
- 2026-07-25 — **Attendance card polish + interactions round 2.** Both card pills now share one **`StatusPill`** style (Status Kehadiran was a filled `NBBadge`, Status Area an outline pill — now consistent), and the two rows are a fixed height so they line up; the Status-Area **refresh** shrank to match the row (28 px NB box, 15 px glyph). The out-of-area **notice** ("Anda berada di luar area kerja. Absen tetap dicatat.") is back on the record page (below the pills). Detail Shift modal values are **right-aligned** (label left / value right); the Area Tugas map's info strip spacing was tidied (single `gap`, no stacked margins). The Notifications back button now does a real **stack pop** so it plays the inverse slide-out (was a nested `navigate` that skipped the animation).
- 2026-07-25 — **Simplified attendance card + interactive pills (home & Rekam, shared).** The card was too dense, so it now shows only the at-a-glance state — MASUK/KELUAR, **Status Kehadiran** pill, **Status Area** pill (with the NB refresh beside it), and the Detail Shift link. Everything else (Jadwal Shift, Mulai clock in, Durasi, Waktu Sekarang, Area Ditugaskan, Lokasi sekarang coordinates) moved **into the Detail Shift modal** (`ShiftDetailModal` gained optional `shiftText`/`durationText`/`currentTime`/`currentLocation` props). Two new interactions, both shared by the home hero and the Rekam Kehadiran card: tapping the **Status Kehadiran** pill opens a new **`AttendanceStatusSheet`** explaining *why* it reads Terlambat / Tepat Waktu / Tanpa Jadwal (with clock-in vs scheduled-start times); tapping the **Status Area** pill opens the **Area Tugas** map (`LocationMapModal`), which now has its own **refresh** button too. `AttendanceInfoRows` slimmed to the two pill rows + Detail Shift; `AttendanceStatusSheet` + updated screen/modal tests.
- 2026-07-25 — **Unified attendance card — identical rows on home + Rekam, exact order.** The home "Kehadiran" hero and the Rekam Kehadiran card now render the SAME labelled rows in the SAME order via **`AttendanceInfoRows`** (`components/attendance/`, `attendance:infoCard.*` keys): MASUK/KELUAR summary → **Jadwal Shift · Status Kehadiran · Mulai clock in · Durasi · Waktu Sekarang · Area Ditugaskan · Status Area · Lokasi sekarang** (coords + accuracy + refresh icon) → Detail Shift. The only differences are on the record page: the **"Jenis Kehadiran"** switch (first row) and the out-of-area **notes** banner (below Lokasi sekarang). Removed the clutter: Rekam's separate `GPSLocationSection` (its coords/accuracy/"Perbarui GPS" are folded into the Lokasi sekarang row) and the big **"Waktu Shift" HH:MM:SS timer block** (redundant with the Durasi + Mulai clock in rows). `useClockInOut` now exposes `attendance` (for MASUK/KELUAR on the record page); a live `now` clock drives Waktu Sekarang on home. `AttendanceInfoRows` unit test (6) + screen tests updated (accuracy → `±Nm`, duration → HH:MM, refresh via `attendance-refresh-location` testID).
- 2026-07-25 — **"Rekam Kehadiran": one reusable page + attendance-type picker (PR2 of the cross-midnight work).** The clock-in/out screen's header is now the stable page name **"Rekam Kehadiran"** (was the swapping "Clock In"/"Clock Out"), and the action is chosen in-page: a new **attendance-type selector** row (label + "Ubah Label Waktu" link → `AttendanceTypeSheet`, a Clock In / Clock Out radio picker) drives the primary button. The label **defaults from shift state** — an open shift → Clock Out, none → Clock In — but the worker can override it for a dangling/overrun shift or back-to-back shifts. Because SEKAR holds at most one open shift, the label that can't currently proceed (clock in with a shift open, or clock out with none) is flagged in the picker and blocks the button with an inline warning, so the screen never submits a doomed action. Pairs with the PR1 resolver fix so a forgotten past-midnight shift now shows its real schedule/area AND is clocked out from this same page. New i18n keys under `attendance:clockInOut`; `AttendanceTypeSheet` unit test + updated clock-in/out screen tests (submit targeted by `testID`). The selector later moved **inside** the Informasi Kehadiran card (first row, card opens expanded).
- 2026-07-25 — **Home & clock-in map unified (one builder, identical pins).** The home hero's "Status Area" map and the clock-in/out "Lihat di peta" map now render the same boundary, the same area/worker pins, and the same title ("Area Tugas"). Both are fed by shared `mapUtils` helpers — `buildMapArea` (centre + polygon normalizer, Number-coerces TypeORM string coords and falls back to the polygon's first vertex) plus `workerMapMarker`/`scopeAreaMarker` (role glyph tinted inside/outside · rayon/kawasan/lokasi glyph). `useHomeLocation` now returns the resolved `mapArea`, so `FieldHomeScreen` drops its bespoke inline area-resolution + default pins. Previously the home map drew the rayon boundary with plain Google pins while the clock-out map drew neither boundary nor area pin — they can no longer diverge. (Also: the Notifications inbox push now slides in from the right / out to the right — the platform default — instead of `slide_from_left`.)
- 2026-07-24 — **Map fix: coerce the area centre coordinate.** `LocationMapModal` passed the area's `gps_lat`/`gps_lng` straight to react-native-maps' `<Marker>`; TypeORM emits decimal columns (e.g. a district's `center_lat`) as **strings**, which crashed the native marker with "Value for latitude cannot be cast from String to double" when opening the map from the home hero. The modal now `Number()`-coerces the area centre (the user coordinate already was), so it's safe for every caller — clock-in, clock-out, home.
- 2026-07-24 — **Shorter scope labels + scope-aware home hero.** The scope i18n keys dropped their prefix — a rayon assignment now reads **"Rayon Barat 1"**, not "Lingkup Rayon Rayon Barat 1" (the district is already named "Rayon …"), everywhere the scope shows (home, clock-in, roster, detail). On the home "Kehadiran" hero, the in/out-area **pill shows in the header only while collapsed** and moves into the body ("Status Area" row) when open. `useHomeLocation` is now **scope-aware** — it geofences a rayon/kawasan assignment against its own boundary (was lokasi-only, so scope workers never got a real inside/outside) and exposes `hasBoundary`; the home map draws that boundary too.
- 2026-07-24 — **Clock-in map/status refinements.** `isWithinBoundary` is now **derived** from the current location + assigned areas (was set inside the GPS callbacks, which went stale when the roster loaded after the last fix or the mock GPS stopped ticking — the map could read "di dalam" while the marker sat outside); the on-open fix is also forced fresh (`maximumAge: 0`). The status pill returns to the card **header while collapsed** and hides when open (the body "Status" row carries it) via a new function-form `headerRight` on `NBCollapsibleCard`. "Lihat di peta" moved to the **right column of the "Lokasi terekam" row** (single row). The map modal is renamed **"Area Tugas"** and now draws **web-style pins** — the worker by role glyph (`getRoleIcon`, tinted inside/outside) and the area by a rayon/kawasan/lokasi glyph.
- 2026-07-24 — **Clock-in: Status row, GPS map modal, one area indicator.** The on-time/late pill moved from the card header into the body as a labelled **"Status"** row (below Jadwal Shift). The within/outside **pill was removed** — it duplicated the status alert — and the alert itself is now **tappable to open a map** (`LocationMapModal`, reused from the home "Lokasi Anda") that draws the worker's GPS marker against the boundary they're assigned to, so "luar area" is actionable (you can see where to move). `useClockInOut` exposes `mapArea` (the geofenced lokasi/rayon/kawasan boundary + centre). "Jadwal Saya" is now a hidden feature **tab** (like Tugas/Absensi) instead of a MainStack push, so its entry transition matches every other page (no more `slide_from_left`).
- 2026-07-24 — **Scope-aware geofencing + clock-in card cleanup.** A rayon/kawasan assignment is now geofenced against its OWN boundary polygon (rayon→rayon, kawasan→kawasan, lokasi→lokasi), not treated as "tanpa batas lokasi, attendance always recorded". `useClockInOut` builds a geofence area from `roster.district`/`roster.region.boundary_polygon` (already loaded by `findAllByUserAndDate`; the range query `findByDateRangeForUser` now joins `district` too for parity), so `areaState` reads `within`/`outside` for scoped assignments and only falls back to the neutral `scope` state (fail-open, attendance still recorded) when a scope genuinely has no polygon — labelled "batas area belum ditentukan", not the old misleading copy. UI: the two clock-in cards ("Informasi Kehadiran" + "Lokasi GPS") are merged into one; the duplicated GPS readout (status-row coords + detail block) is collapsed to a single labelled block; and the redundant "Ditugaskan se-Rayon — tanpa lokasi tertentu" line is removed. Note: an emulator's default Jakarta GPS reads LUAR AREA against a Surabaya rayon — set a Surabaya mock location to verify DI AREA.
- 2026-07-23 — **"Lokasi Anda" draws the right boundary, and it matches monitoring.** The map took its area from `currentShift?.area ?? assignedArea` — the ACTIVE clock-in or the *permanent* lokasi — skipping today's roster entirely, so a worker whose schedule sent them somewhere other than their permanent lokasi saw the wrong boundary, or none at all, on the very screen meant to answer "am I in my area?". Priority is now active clock-in → today's roster lokasi → permanent. The polygon is styled from the monitoring palette instead of the pruning-request one and is **tinted by whether the worker is inside it**, so it cannot contradict the badge above it, and the lokasi's own pin is drawn so the area stays identifiable when the worker is far outside it.
- 2026-07-23 — **Clock-in geofences against TODAY'S assignment, and shows all of it.** `useClockInOut` built its geofence from the standing `assignedAreas`, not the roster — so whenever today's assignment differed from the permanent one, clock-in was checked against the wrong lokasi. It now prefers today's roster lokasi, lists **every** covered lokasi when there is more than one ("clock in diterima di salah satu lokasi di atas"), and treats a kawasan/rayon/kota-scope day as boundary-free rather than area-less — the backend resolves the actual lokasi from GPS, expanding the scheduled kawasan.
- 2026-07-23 — **"Jadwal Saya" card on the mobile home.** A worker could not see their own assignment from the home screen at all — today's shift window, scope (lokasi / kawasan / rayon / kota) and team now render in a tappable card that opens the full day view. Shown for clockable roles only; falls back to "Tidak ada jadwal hari ini".
- 2026-07-22 — **Clock-in told the truth about lateness and scope (mobile).** (1) The attendance badge judged lateness from the *first clock-in*, which does not exist yet on the Clock In screen — so a Shift 1 (06:00–15:00) worker opening it at 21:54 was shown **TEPAT WAKTU**. `deriveAttendanceStatus` now projects against **now** ("if I clock in this second, am I late?") and adds an `outside_window` state for a shift whose window has already closed. (2) A **city/rayon/kawasan-scope** schedule names no lokasi, and both the home hero and the clock-in card read that as unassigned — "Anda belum ditugaskan ke area manapun" for a worker assigned across all of Surabaya. New `utils/scheduleScope.ts` `resolveScheduleScope(roster)` (lokasi → kawasan → rayon → city, most specific wins) labels the real scope; only a worker with **no roster row** is called unassigned. (3) **"Jadwal Saya" added to the Menu grid** for every schedulable role — the screen existed but was reachable only from Profil.
- 2026-07-17 — **Fix ad-hoc clock-in 500 (`shifts.location_id` NOT NULL drift).** The `Shift` entity declares `location_id` nullable and `clockIn` explicitly allows an **ad-hoc clock-in with no area** (worker with no schedule + no assigned area; GPS still recorded), but the DB column was created `NOT NULL`, so that path threw a raw not-null constraint error (HTTP 500) instead of recording the shift. Migration `MakeShiftLocationNullable` drops the constraint to match the entity + intent. Behaviour-preserving (all existing shifts have a location); only the previously-impossible ad-hoc insert now succeeds (verified: `POST /shifts/clock-in` for an unassigned worker → 201 with `location_id: null`).
